# Prepare a JLCPCB assembly order

JLC needs three files that agree with each other: a Gerber zip with the drill files in it, a BOM and a CPL. The
three ways orders go wrong:

* **Two origins.** JLC lines the CPL up with the Gerbers. Gerbers from the page origin with a CPL from the drill/place
  origin shift every part by the same vector. Export all of them from the drill/place (aux) origin.
* **The Y axis.** KiCad's board coordinates, in the file and in the editor's status bar, have Y pointing down. JLC's
  CPL, like the Gerbers, has Y pointing up. A row typed or scripted from KiCad's coordinates has its Y sign wrong.
  kicad-cli's position file and `jlcplace cpl` already flip Y. Never mirror Y in the drill export, and never negate X
  for bottom parts.
* **KiCad's own angles.** A KiCad position file carries KiCad's rotations and anchors. JLC uses EasyEDA's, which
  often differ. Write the CPL with `jlcplace cpl`.

## Steps

Work in a `fab/` directory next to the board (or wherever the project keeps its fab outputs). Ask before overwriting
files that are already there. If the project already makes its fab outputs with a script or a release pipeline (look
for one, and for notes such as "generated by ...; do not edit" next to its outputs), run that and check its outputs
with step 6 instead of making a second set. Use its file names, and ask before writing next to them.

1. **Tools.** Run `jlcplace --version`. If it is missing, follow [setup-jlcplace](../setup-jlcplace/SKILL.md). Then
   run `kicad-cli version`: KiCad 8 or later exports everything below. Without kicad-cli, have the user follow the
   GUI steps in [kicad-gui.md](kicad-gui.md) for steps 3 and 4, then continue at step 5.
2. **The origin.** Look for `(aux_axis_origin X Y)` in the board's `setup` section. If it is there, every file below
   uses that point. If not, the drill/place origin is the page origin (0, 0), which is consistent too. Do not move an
   existing origin, because earlier orders and fixtures may depend on it. The usual place for a new one is the board's
   lower-left corner (in KiCad: Place > Drill/Place File Origin).
3. **Gerbers and drill files**, both from the drill/place origin. List the inner copper layers with
   `grep -oE '"In[0-9]+\.Cu"' board.kicad_pcb | sort -u`, and add them to `--layers` (a 2-layer board has none):

   ```sh
   mkdir -p fab/gerbers
   kicad-cli pcb export gerbers board.kicad_pcb -o fab/gerbers/ --use-drill-file-origin \
     --layers F.Cu,In1.Cu,In2.Cu,B.Cu,F.Paste,B.Paste,F.Silkscreen,B.Silkscreen,F.Mask,B.Mask,Edge.Cuts
   kicad-cli pcb export drill board.kicad_pcb -o fab/gerbers/ --drill-origin plot --excellon-units mm --excellon-separate-th
   (cd fab/gerbers && python3 -m zipfile -c ../board-gerbers.zip *)
   ```

   Do not use `--excellon-mirror-y`, and do not leave out `--use-drill-file-origin` or `--drill-origin plot`. The
   defaults use the page origin. `--excellon-separate-th` writes the plated and the non-plated holes to separate files
   (`-PTH.drl`, `-NPTH.drl`). Without it they share one file, where only per-tool attributes mark the non-plated
   holes (mounting holes, connector pegs) as unplated. If `fab/gerbers/` holds an earlier plot, ask, then empty it
   before plotting: KiCad never deletes old files, and two plots in one zip are red in step 6.
4. **BOM with LCSC codes.** Find the schematic field that holds the codes:
   `grep -ohE '\(property "[^"]*(LCSC|JLC)[^"]*"' *.kicad_sch | sort | uniq -c`. It is often `LCSC`, `LCSC Part` or
   `JLCPCB Part #`. Export from the root schematic (the one named like the project), with that field in place of
   `LCSC`:

   ```sh
   kicad-cli sch export bom board.kicad_sch -o fab/board-BOM.csv \
     --fields 'Value,Reference,Footprint,LCSC,${QUANTITY}' --labels 'Comment,Designator,Footprint,LCSC Part #,Qty' \
     --group-by 'Value,Footprint,LCSC' --ref-range-delimiter '' --exclude-dnp
   ```

   `--ref-range-delimiter ''` writes `R1,R2,R3`, not `R1-R3`. Check the file: every part JLC should assemble needs a
   code (`C` and digits). Parts without one are not assembled. Ask the user about each one, unless it is
   intentionally hand-soldered or board-only.
5. **CPL.** Write it with jlcplace, following [write-jlc-cpl](../write-jlc-cpl/SKILL.md). It needs the EasyEDA
   records: ask before running `jlcplace fetch board.kicad_pcb --bom fab/board-BOM.csv`, which downloads them once.

   ```sh
   jlcplace cpl board.kicad_pcb -o fab/board-CPL.csv --bom fab/board-BOM.csv --gerbers fab/board-gerbers.zip --db jlcplace-db --checklist fab/checklist.md
   ```

   With `--gerbers`, the rows are written from the Gerbers' own (0, 0), the origin JLC reads them from, and Gerbers
   that are not this board's as it is are red (see step 6). Keep `--db jlcplace-db` (or the project's own database)
   even before it exists: `jlcplace confirm` creates it when the first decision is recorded, and until then jlcplace
   only warns that it does not exist. Resolve every red row as that skill says (a numbering or polarity decision is
   the user's to make) until the file is written.
6. **Final check** of exactly the files that will be uploaded, the Gerber zip included:

   ```sh
   jlcplace check board.kicad_pcb fab/board-CPL.csv --bom fab/board-BOM.csv --gerbers fab/board-gerbers.zip --db jlcplace-db --checklist fab/checklist.md
   ```

   jlcplace finds where the Gerbers' (0, 0) lies on the board and checks the rows from there, as JLC lays them over
   the Gerbers: the first line says `origin 100, 100 from the Gerbers (aux)`. It must exit 0, with no red line and no
   `BOM` line. A red line before the rows is about the whole order (a finding):
   * `origin mismatch: JLC lays the CPL over the Gerbers from their (0, 0), ... but the CPL was written from ...`:
     the CPL and the Gerbers use different origins. Its `fix:` names the ways out: re-export steps 3 and 5 from one
     origin, or write the CPL with `--gerbers` as in step 5.
   * A `gerbers` finding: the zip is mirrored, in the wrong unit, another board's, older than the board (re-plot it,
     step 3), lacks a side's copper (its paste: yellow), or holds two plots (KiCad never deletes an old plot: empty
     `fab/gerbers/` and plot again).

   jlcplace does not read the drill files: they are right when step 3 wrote them with `--drill-origin plot`. Explain
   each yellow row ([check-jlc-placement](../check-jlc-placement/SKILL.md)).

## Before uploading

Go through this list with the user and say which items are done:

- [ ] Gerbers and CPL from one origin: step 6 says `from the Gerbers`, with no red `origin` or `gerbers` line.
      The drill files from that origin too (`--drill-origin plot`).
- [ ] The zip holds every copper layer of the board, both masks, both silkscreens, both pastes, Edge.Cuts and the
      `.drl` files (plated and non-plated holes in separate files).
- [ ] The BOM lists an LCSC code for every part to be assembled, and `jlcplace check --bom` printed no `BOM` line.
- [ ] The CPL was written by `jlcplace cpl` from the same board revision as the Gerbers, and in mm.
- [ ] `jlcplace check` exits 0. Every red row is fixed, and every yellow row is understood.
- [ ] DNP parts are in neither the BOM nor the CPL.
- [ ] Bottom-side parts: the order assembles the side(s) the CPL's Layer column names.
- [ ] `fab/checklist.md` is ready for JLC's placement preview.
- [ ] No HTML report, overlay image or EasyEDA record in the upload or the repository. The correction database
      (`jlcplace-db/`) and the checklist can be committed.

Then the user uploads the zip, the BOM and the CPL on JLC's order page. When JLC substitutes a part, put the new
code in the BOM and run steps 5 and 6 again, because another part can have another footprint. Before paying, walk
JLC's placement preview with [review-jlc-preview](../review-jlc-preview/SKILL.md). It is the only check of the
bottom-side reading and of what the checklist lists.
